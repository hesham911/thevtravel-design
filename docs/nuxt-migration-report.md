# TheVTravel framework migration report

Verified on 3 October 2026. This is a framework migration of the approved Vue implementation. All seven original CSS files and all demo-data files were preserved byte-for-byte. Public assets and fonts were retained.

1. **Installed framework:** Nuxt 4.5.2, Vue 3.5.42, Nitro 2.13.4. SSR is enabled. The Node engine requirement is recorded in `package.json`.
2. **Obsolete files removed:** `src/main.js`, `src/App.vue`, `src/views/`, and the remaining migrated `src/` tree; `vite.config.js`, the SPA `index.html`, and obsolete `dist/`. Direct Vite and `@vitejs/plugin-vue` dependencies were removed after successful Nuxt build/run checks. Nuxt retains its internal Vite builder. Vue Router, Vue, Leaflet, icon libraries and DOMPurify remain available. Original source and configuration are archived in `artifacts/vite-source-before-migration.tar.gz`.
3. **Directories migrated:** components → `components/`; composables → `composables/`; static content → `data/`; adapters → `services/`; helpers → `utils/`; all CSS → `assets/css/`. `public/` assets remain at their approved URLs. Added `app.vue`, `nuxt.config.ts`, preference/bootstrap plugins, and `app/router.options.ts`. No unused layouts, middleware, server endpoints or CMS abstractions were introduced.
4. **Route mapping:** existing public URLs and named routes are retained. Legal routes still use the shared `LegalContentPage` renderer and route-specific legal records.

5. **Unchanged components:** ten components are byte-for-byte copies: `components/JourneyListingCard.vue`, `components/AppIcon.vue`, `components/BottomJourneyCTA.vue`, `components/HeroRouteLine.vue`, `components/BrandIcon.vue`, `components/NeedHelpCTA.vue`, `components/journey/JourneyIcon.vue`, `components/journey/JourneyBookingSummary.vue`, `components/journey/RelatedJourneys.vue`, `components/journey/JourneyGalleryViewer.vue`. All 25 original components are retained.
6. **Adapted components:** the other 15 retain their templates and component hierarchy, with targeted import-path, NuxtLink, preference-state, runtime configuration, map-loading or legal-sanitization changes. Header/TransferBanner/floating actions capture per-app state during setup. Journey request steps, validation, review and its existing draft-emission contract are preserved. Transfer retains its existing three-step flow and local-storage success behavior. See `artifacts/nuxt-component-migration.json` for the exact file lists.
7. **Browser boundaries:** only `ServiceAreaMap` and `TransferMapPicker` sit inside `ClientOnly`, with dynamic imports to prevent Leaflet evaluation on the server. Resize/Intersection observers run on mount; storage restoration runs after hydration; dialog DOM/focus logic runs in client events. Mutable locale/theme/request state is scoped to the Nuxt app through `useState`, preventing shared SSR-request state. Transfer's current-date value is transferred in the SSR payload and refreshed to the browser-local date on mount.
8. **Leaflet:** retained Leaflet 1.9.4 and the existing OpenStreetMap tile URL, bounds, labels, marker, explicit search, reverse-geocoding contract, geolocation and normalized coordinates. CSS is globally registered so client-only maps retain their styling. Picker teardown stops movement and delays removal until Leaflet's pending 250ms zoom callback has settled; this prevents a confirmed-while-zooming DOM error without changing visible interaction.
9. **SSR:** useful HTML was verified directly over HTTP for all 45 public routes, including all 37 Journey slugs. Every route returned 200 with an H1, title and description. **Journey Details server HTML contains the record's title and overview content. No whole page was forced into client-only rendering.** Legal empty-state content is server rendered, matching the supplied demo records.
10. **SEO:** `useSeoMeta` and `useHead` derive titles/descriptions from route metadata and the actual Journey record. Abu Simbel has Abu Simbel metadata. `NUXT_PUBLIC_SITE_URL` enables absolute canonical URLs, Open Graph URL and Journey image URL. Query/tab state does not create separate canonicals. No deployment domain was fabricated. The demo records remain directly usable; future SSR fetches can replace these boundaries with `useAsyncData`/`useFetch`.
11. **Theme hydration:** SSR reads the theme cookie. A small pre-paint script preserves legacy localStorage/system-theme initialization, and the mounted preference plugin synchronizes it with per-app state and the cookie. Explicit toggles retain the old localStorage key. Approved colors and floating-action opacity are unchanged.
12. **Language hydration:** English is default. EN/RU/FR/DE use the existing translation catalog and shared fallback fonts. SSR reads the language cookie; legacy localStorage preference is adopted after hydration and persisted to a cookie for subsequent matching SSR. Locale remains independent of route structure so prefixed localized routes can be added later. Existing dropdown markup, geocoding locale mapping and URLs are preserved.
13. **Environment migration:** `VITE_WHATSAPP_URL` → `NUXT_PUBLIC_WHATSAPP_URL`; `VITE_LOCATION_API_URL` → `NUXT_PUBLIC_LOCATION_API_URL`. Added empty `NUXT_PUBLIC_API_BASE_URL` for future integration and `NUXT_PUBLIC_SITE_URL` for deployed canonical/OG URLs. Values are read through `runtimeConfig.public`. No secret/provider API key is exposed. `.env.example` documents these settings.
14. **Laravel/Admin readiness:** no API integration, fake static-data fetches, new provider or image module was introduced. Demo/CMS content boundaries, localized rich HTML, currency helpers and normalized map adapters are preserved. Legal HTML uses isomorphic DOMPurify on server/client with the same restrictive allowlist, plus accessible table wrappers; sanitization was not weakened.
15. **Tests/build:** `npm test` passes all 13 tests: the original 11 currency/location/map-search tests and two added server-side legal tests. Nuxt dev, production build and production preview all run. Direct requests/refreshes and cookie-localized SSR pass. Browser interactions verify Journey validation/review, Transfer review/success/storage, Escape, scroll lock, floating-action suppression, progressive loading, sort/view/batch/scroll restoration, preferences and mobile navigation. Mocked proxy tests verify explicit search, reverse geocoding, current location and both location confirmations.
16. **Responsive/browser verification:** Chrome checked every combination of 320, 360, 390, 430, 768, 1024, 1280 and 1440px; Light/Dark; EN/RU/FR/DE. There are **896 public-page/Journey-tab comparisons** covering Home, listing, six Details tabs, Contact, About, FAQ, booking explanation and both legal routes, plus **192 Journey/Transfer/Map Picker comparisons**. Visible text, positions/sizes, fonts, weights and colors match. 128 equivalent SVG URL-versus-inlined-data references are recorded separately; geometry and styling match. Map-picker screenshots were also inspected. **No hydration warnings or browser console errors remain in the completed checks. No known design differences remain compared with the approved Vue version.** This is geometry/computed-style comparison with sampled screenshot review, not a claim of an exhaustive pixel-diff across browsers. Safari and Firefox were not tested.
17. **Remaining considerations:** there are no known functional migration issues in the verified paths. Legal copy, real WhatsApp configuration and geocoding proxy configuration remain dependent on the same inputs as before; no copy, contact URL or provider was invented. Actual Journey/Transfer backend submission remains a future integration, preserving the current demo contracts. Canonicals/absolute OG images require the production origin setting. A first visit with only a legacy language preference adopts it after hydration; later visits use cookie-matched SSR. `npm audit` reports 11 high advisory paths from upstream `braces` and `node-forge` dependencies; the installed versions are the latest reported by the registry during verification. Details are preserved in `artifacts/nuxt-dependency-audit.json`.
